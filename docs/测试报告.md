# 测试报告

> 测试对象：LingoGuard 0.1 本地化预检台（Issue #2 课程原型）。以下命令和输出在 2026-11-04 的本机环境实际执行；示例数据均为合成数据。

## 1. 结论

- 自动化测试：**103 个测试通过**（`python3 -m unittest discover -s tests -v`，0.834s）。
- 可复现批量流：`scripts/check.py` 对 28 条中→葡演示数据完成导入、检查、JSON/CSV/XLIFF 导出；`--fail-on error` 返回退出码 1。
- 浏览器交叉检查：Chrome 156 无头模式载入页面后，28 条 unit 正常渲染，Noto Sans 字体加载成功，页面无横向滚动；`settings.tab.settings` 的 DOM 实测与 Pillow 判定一致（均判溢出）。
- 核心检查可测试；消歧/源文缺口/修辞仍为实验性启发式，不能表述为“语义理解”或“语法正确性验证”。

## 6. 失败/边界样本（必须保留）

这些不是“待修 bug”，而是原型主动承认的边界：

1. **CJK 不测量**：`设置` 在 Noto Sans 下无 CJK 字形，返回 `OVF000`，不拿 tofu 宽度冒充测量。
2. **ICU 模板不测量**：`{count, plural, ...}` 需运行时分支渲染，返回 `OVF000`，不测原始模板字面量。
3. **无类型占位符不猜语法**：`{0}` 只验证保留/重排；`PH012` 只提示“可能存在数量影响”，明确写“不判断目标语语法正确性”。
4. **字体假设**：不模拟自动缩放、富文本内联样式、fallback 字体链、引擎布局；结果只在该字体/字号/字距/文本框/行高/行数假设下成立。
5. **消歧不是理解**：义项库是 7 个合成词条；关键词/元数据可能误判；无证据时弃答。
6. **XLIFF 限制**：v0.1 展平 `<g>/<ph>`，不支持 XLIFF 2.0。
7. **没有真实项目/厂商数据**：不声称商业优势；CAT/TMS 重叠见方案比较。

`report.csv` 以 `EF BB BF`（UTF-8 BOM）开头，便于 Excel 打开中文/葡语；`checked.xliff` 可被 `parse_xliff` 回导为 28 条 unit（`tests/test_engine.py` 覆盖）。
