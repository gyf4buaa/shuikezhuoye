# 接入说明：从现有资源到批量预检

> 目标：说明 CSV/XLIFF 批量流怎么接、UI 元数据从哪里来、哪些仍需人确认。示例均为合成数据。

## 1. 接入前需要准备什么

| 数据 | 来源 | 是否必须 |
|---|---|---|
| `id` | 字符串表主键、CAT/TMS 导出、代码扫描 | 必须，批次内唯一 |
| `source` | 源文导出 | 必须 |
| `target` | 目标语导出 | 必须（允许空，但会提示 `PH013`） |
| `key` | 字符串 key | 消歧需要；缺失会降低覆盖率 |
| `screen` | 界面/场景路径 | 消歧需要 |
| `component` | 控件类型（button/tab/label/entry/...） | 消歧需要 |
| `neighbors` | 同屏/同组件相邻文案 | 消歧需要；可从资源按 screen 聚合 |
| `max_chars` | 现有设计预算 | 可选；只做字符基线 |
| `ui.profile` | 目标 UI 盒模型名 | 可选；不填用默认 profile |
| `ui.box_w/box_h/font_size/...` | 设计稿、引擎 UI 配置 | 可选；覆盖 profile |

关键原则：**缺失的上下文不会被要求逐条手填**。工具显示 key/screen/component/neighbors 覆盖率；不足的条目标“需上下文/弃答”，并列出需要补什么。

## 2. CSV 批量流

### 2.1 字段

```csv
id,source,target,key,screen,component,neighbors,max_chars,profile,box_w,box_h,font_size,padding,max_lines
settings.tab.audio,音频,Áudio,settings.tab.audio,settings,tab,画面|操作,10,settings_tab,110,36,16,6,1
lore.world_setting,世界观设定,Configurações,lore.world.codex,codex,entry,剧情|词条,12,mobile_dialog,280,72,16,10,2
```

- `neighbors` 用 `|` 分隔；不要用逗号，避免与 CSV 分隔符冲突。
- `profile` 与 `box_*` 可同时出现；`box_*` 覆盖 profile 的单字段。
- 文件头可写 `# project=...`、`# source_locale=zh-CN`、`# target_locale=pt-BR`。
- CSV 按 UTF-8 保存；CLI 导出带 BOM，便于 Excel。

### 2.2 最小示例

```bash
cat > /tmp/strings.csv <<'CSV'
# project=接入示例
# target_locale=pt-BR
id,source,target,key,screen,component,neighbors
a,设置,Configurações,settings.tab.audio,settings,tab,画面|操作
b,确认,Confirmar,common.confirm,dialog,button,
CSV
python3 scripts/check.py /tmp/strings.csv --out out/import-demo --format csv
```

## 3. XLIFF 1.2 批量流

导入标准 `trans-unit`：

```xml
<trans-unit id="settings.tab.audio">
  <source>音频</source>
  <target>Áudio</target>
  <note from="dsh-context">{"key":"settings.tab.audio","screen":"settings","neighbors":["画面","操作"],"ui":{"profile":"settings_tab"}}</note>
</trans-unit>
```

- 本工具导出时会把上下文写入 `from="dsh-context"` 的 JSON note，把问题写入 `from="dsh-issue"`。
- 其他工具导出的纯文本 XLIFF 可直接导入；没有 note 时上下文覆盖率为 0，消歧会更多弃答。
- v0.1 会把内联 `<g>/<ph>` 展平为文本；这会丢失内联结构。若项目依赖内联标签，请先用占位符/标签检查，或等待后续版本。
- 不支持 XLIFF 2.0。

## 4. UI 盒模型

`data/ui_profiles.json` 内置 7 个**合成** profile：

| profile | 字号 | 盒宽×盒高 | 行数 | 行高 | padding |
|---|---|---|---|---|---|
| `mobile_dialog` | 16 | 280×72 | 2 | 1.4 | 10 |
| `settings_tab` | 16 | 110×36 | 1 | 1.3 | 6 |
| `inventory_cell` | 13 | 100×48 | 2 | 1.25 | 4 |
| `banner_title` | 22 | 360×44 | 1 | 1.2 | 8 |
| `tooltip` | 16 | 240×72 | 3 | 1.3 | 8 |
| `badge` | 14 | 51×26 | 1 | 1.2 | 4 |
| `micro_badge` | 14 | 38×26 | 1 | 1.2 | 4 |

接入真实项目时：

1. 从设计稿/引擎 UI 配置读取字号、文本框、padding、行高、最大行数；
2. 在 `data/ui_profiles.json` 增加 profile，或直接在字符串行里写 `ui` 覆盖；
3. 确认字体：当前内置 Noto Sans；若目标 UI 用其他字体，需替换 `assets/fonts/` 并同步浏览器 `@font-face`，否则测量结果不对应；
4. 对 `max_lines=1` 的标签，工具只测宽度，不做换行；
5. 最终在目标引擎中确认；Pillow 结果不是引擎布局。

## 5. 目标语言与规则

`target_locale` 影响：

- ICU plural 的 CLDR 必需分类（pt/de/es/fr/en 为 `one,other`，ru/pl 更细，ar 6 类）；
- 部分启发式/展示。

`target_locale` **不会**自动改写已有译文。切换目标语言只改变检查规则和显示；如果译文还是葡语而目标选俄语，工具会按俄语复数分类检查，但不会把葡语翻译成俄语。演示时请使用对应语言的示例数据。

## 6. 接入流程（推荐）

1. **导出**：从 CAT/TMS 或项目字符串表导出 CSV/JSON/XLIFF；保留 id/key。
2. **补充 UI 元数据**：按 screen 聚合 neighbors；按控件选择 profile；填入 max_chars（如果有）。
3. **本地预检**：`python3 scripts/check.py ... --out out/run-日期` 或 Web 页面导入。
4. **分流**：
   - `PH*` / `OVF001` / `CTX002`：通常需要修改译文或模板；
   - `OVF002`：近阈值，优先预留余量；
   - `CTX001`：补 screen/neighbors 或人工指定义项；
   - `SRC*`：向源文作者/策划提问；
   - `REG001`：母语译者确认语域；
   - `OVF000`：换字体/在引擎中实测，不要拿字符数冒充。
5. **回导**：把修复后的译文写回 TMS；本工具不直接回写 TMS，CSV/XLIFF 由现有流程导入。
6. **引擎验证**：对最终文本在目标 UI 中跑真实布局/截图；本工具只做前置筛查。

## 7. 仍需人工的部分

- 证据不足的义项（`CTX001`）：需要 screen/相邻文案/术语表或人工指定；
- 源文省略/时态/指代（`SRC*`）：需要源文作者确认；
- 修辞/语气（`REG001`）：需要母语译者；
- 字体/引擎布局：需要在目标引擎中验证；
- 目标语语法/复数/性数一致：本工具不判断；
- 术语库治理：本工具只用小型合成义项库，不替代项目术语库。

## 8. 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `DatasetError: UI profile ... 必须是对象` | JSON 里 `_notice` 被当成 profile | 已修复：下划线键会跳过；升级代码 |
| `无法测量: CJK` | 当前字体无中日韩字形 | 换目标字体或在引擎中测 |
| `无法测量: ICU plural` | 模板需运行时分支渲染 | 在引擎/运行时按分支测 |
| 上下文覆盖率为 0 | 输入没有 key/screen/neighbors | 补元数据；这是预期行为 |
| 导出 CSV 中文乱码 | Excel 未识别 UTF-8 | 使用 CLI 导出的 BOM 版本，或导入时选 UTF-8 |
| XLIFF 标签丢失 | v0.1 展平 `<g>/<ph>` | 保留原始 XLIFF；等待后续支持 |
