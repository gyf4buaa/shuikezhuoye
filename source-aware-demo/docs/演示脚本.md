# 60 秒现场演示脚本

> 前提：在 `source-aware-demo/` 下执行 `python3 app.py`，打开 <http://127.0.0.1:8010/>。
> 默认**不配置 API Key**也能完整演示前半段；有 Key 时可加演真实对照。

## 0–10 秒：说明目标与边界

页面顶部：

- 指向 `SYNTHETIC · 合成演示工程` 徽标：“这是人工合成的 Unity/C# 小工程，不是真实企业源码。”
- 指向黄色提示条：“当前没有 API Key，所以只做本地检索，不调用模型，页面不会出现 AI 译文。”

一句话定位：**“这不是让模型猜上下文，而是先真实读取源码，再把证据交给模型。”**

## 10–25 秒：选择字符串，展示同文本歧义

1. 左侧点选 **`ui.leaderboard.rank_column`**（源文本 `Rank`）。
2. 指出左侧提示：“`Rank` 同时属于 `ui.leaderboard.rank_column` 和 `ui.military.rank_badge`，所以同一个词在不同界面可能要有不同译法。”
3. 指出统计行：“后端刚刚扫描了 7 个文件 / 170 行，耗时个位数毫秒。”

## 25–40 秒：展示“真实证据”，而不是模型解释

向下滚动到第一条证据卡：

- **路径与行号**：`Assets/Scripts/UI/LeaderboardPanel.cs:17`；
- **代码片段**：`rankColumnHeader.text = L.Get("ui.leaderboard.rank_column");`
- **所在方法**：`LeaderboardPanel.BuildHeader`；
- **推断依据**：`rankColumnHeader / ladder / table / column` 等实际词元，置信度“高”。

再指向第二、三条：

- `LeaderboardPanel.cs:25`、`MilitaryPanel.cs:22` 是**同文本字面量候选**，没有直接引用所选 Key，因此标为“同文本候选 / 需人工确认”，不冒充直接证据。
- 字符串表定义卡片明确写“不提供界面语境”。

一句话：**“这些路径、行号、片段都是刚才从 `demo_project/` 真读出来的；不是写死的示例解释。”**

## 40–55 秒：可选的真实 API 对照

没有 Key 时：

- 指向禁用按钮：“未配置 Key，按钮不可用；结果卡也写明‘未调用模型，因此没有译文’。”

有 Key 时（提前 `export SOURCEAWARE_API_KEY=...` 并重启）：

1. 目标语言选 `pt-BR`，点击 **运行同模型对照翻译（真实调用）**。
2. 说明：“同一个模型、同一组参数，调用两次：A 只给 `Rank`；B 给 `Rank` + 上面的源码路径、行号、片段和推断。”
3. 指向 A/B 卡片：都标 `LIVE · 真实 API 调用`，展示模型、耗时、usage；B 额外展示用了哪些证据。
4. 强调：“这两张卡是真实返回，没有人工审校；如果没有 Key，它们不会出现。”

## 55–60 秒：收束与诚实限制

指向页面底部“边界与限制”：

- 目前只在合成工程验证，**尚未证明能在任意真实游戏中自动找到完整语义**；
- 检索是字面 Key/文本 + 文件扫描，不解析反射、运行时拼接、动态加载；
- 语境分类是启发式，不是编译器/语义分析；
- 只读 `demo_project/`，有路径边界保护；真实企业源码不会默认上传。

收尾：“所以这个 PoC 证明的是‘源码检索 → 证据 → 同模型对照’这条链路可运行，而不是宣称已经解决开放世界游戏的全部本地化语义。”

## 备用：30 秒 CLI 兜底

如果浏览器现场出问题：

```bash
cd source-aware-demo
python3 scripts/lookup.py ui.leaderboard.rank_column
```

输出含真实 `路径:行号`、片段与推断，不依赖 Web 服务，也不会调用模型。
