# 设计说明：源码检索 → 证据 → 可选同模型对照

## 1. 目标与非目标

目标：在一个**合成**的小型 Unity/C# 风格工程上，证明一条可本地运行的链路：

```text
选择字符串 Key
  → 后端真实扫描工程文件
  → 返回路径 / 行号 / 代码片段 / 结构性推断
  → （可选，配置 API 时）用同一个模型对照“只给文本”与“源文 + 证据”的翻译
```

非目标：

- 不证明能自动、完整地理解任意真实游戏的语义；
- 不替代 CAT/TMS，不评估商业翻译质量；
- 不把模型推断或预写解释当作源码证据；
- 不上传真实企业源码。

## 2. 目录与职责

| 模块 | 职责 |
| --- | --- |
| `demo_project/` | 明确标注合成的 C# 面板、JSON/CSV 字符串表 |
| `sourceaware/catalog.py` | 读取字符串表、计算表内行号、计算同文本 Key |
| `sourceaware/retrieval.py` | 只读扫描、匹配、截取片段、定位类/方法、启发式语境推断 |
| `sourceaware/translate.py` | OpenAI-compatible 两次调用、证据字符上限、解析、脱敏 |
| `sourceaware/server.py` | 标准库 HTTP API、静态资源、路径边界、错误处理 |
| `web/` | 无构建的 HTML/CSS/JS 界面 |
| `tests/` | 53 个标准库 unittest（无网络） |

## 3. 检索算法（确定性）

### 3.1 匹配

对字符串表中的每个 Key：

1. **Key 引用**：用带边界正则 `(?<![\w.])KEY(?![\w.])` 搜索，避免 `ui.reward.claim` 误命中 `ui.reward.claim_all`；
2. **同文本字面量**：解析行内双引号字符串，只有内容**完全等于**源文本才命中（`"Rank"` 命中，`"Rank Up"` 不命中）；
3. 同时收集 `Assets/Localization/*.json|csv` 中的表定义。

每条命中记录：

- 相对路径、1-based 行号、列号；
- `direct`：是否直接引用了所选 Key；
- 命中类型：`code-key` / `code-literal` / `string-table`；
- ±2 行片段（带真实行号，命中行标记）；
- 类/方法（C# 花括号 + 方法签名启发式）。

### 3.2 安全边界

- 根目录固定为 `demo_project/`；
- 文件 `resolve()` 后必须仍位于根目录；符号链接跳过；
- 只读 `.cs` / `.json` / `.csv`；单文件 256 KB；结果上限 40 条；
- `key` 参数只用于查表，不拼接文件路径。

## 4. 同文本歧义的处理

`Rank` 同时属于两个 Key。检索结果区分：

- **直接引用**：该行确实调用了所选 Key；
- **同文本候选**：该行只有相同字面量，未引用所选 Key，可能属于其他 Key。

界面上候选证据使用黄色标注并要求人工确认，不会被说成“该 Key 的使用位置”。

## 5. 启发式推断（明确不是语义分析）

从命中行与上下文中提取真实标识符/注释词元，按词表打分：

| 类别 | 触发词元示例 |
| --- | --- |
| 按钮/交互 | button、onClick、AddListener、interactable |
| 列表/表头 | column、header、row、table、leaderboard、ladder |
| 等级/身份 | badge、profile、career、military、fleet |
| 回退/硬编码 | fallback、IsNullOrEmpty、editor、preview、TODO |
| 文本展示 | title、label、text |

输出 `categories`、实际命中的 `signals`、`confidence`、`needs_human`。置信度规则：

- 直接引用 + 得分 ≥3：high；
- 直接引用 + 得分 ≥1：medium；
- 同文本候选：low；
- 字符串表定义：none（并明确“不提供界面语境”）。

UI 将推断标为“确定性启发式”，并展示依据词元；没有证据时输出“证据不足以判断”。

## 6. 翻译对照设计

配置 API Key 后，使用**同一个模型、同一 temperature=0、同一 max_tokens**：

- A（baseline）：
  - system：游戏本地化译者 + 严格 JSON 输出；
  - user：只有源文本。
- B（contextual）：
  - 同一 system prompt；
  - user：源文本 + Key + 证据块（路径、行号、片段、推断）。

约束：

- 证据字符上限 `SOURCEAWARE_MAX_CONTEXT_CHARS`（默认 4000），超出按完整证据条目截断并标记；
- 单次超时、输出 token 上限；
- 结果解析严格 JSON；解析失败则展示原文并标记 `parsed_json=false`，不伪造 rationale；
- 错误信息中的 Key 会被替换为 `[redacted]`；
- 响应包含模型名、耗时、prompt 字符数、usage、实际使用的证据 ID。

## 7. 无 Key 的行为

`LLMConfig.enabled` 为假时：

- `Translator.compare` 直接返回 `status: "disabled"`；
- `baseline` / `contextual` 为 `null`；
- 消息固定包含“未调用模型”；
- Web 按钮禁用，结果卡显示“未调用模型，因此没有译文”；
- 测试通过注入 `transport` 覆盖 live 分支，fake 输出只存在于测试进程，绝不进入 UI。

## 8. 已知限制

- 合成工程是人工设计的，字符串复用与代码结构都偏向演示；
- 只做字面检索，对反射、拼接、运行时格式化、数据绑定、动态资源无解；
- 类/方法定位是启发式，复杂语法（表达式体、局部函数、嵌套类型）可能退化；
- 语境分类可能误判，故始终展示依据与置信度；
- 真实模型质量、目标语语法、术语一致性均未评估；
- 未接入真实游戏引擎、真实字符串导出或 CAT 工具。
